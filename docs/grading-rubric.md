# Grading rubric

The following 100-point rubric can be used for any project. The selected project’s acceptance criteria determine what counts as a complete implementation.

| Category | Points | Evidence |
|---|---:|---|
| Problem definition and scope | 10 | Clear users, inputs, outputs, assumptions, and feature boundaries |
| Data-structure and algorithm correctness | 25 | Required structure/algorithm implemented correctly; invariants and edge cases addressed |
| Functional completeness | 20 | Required operations work together and produce correct results |
| Complexity and performance analysis | 15 | Big-O reasoning, input variables, and measurements or operation counts where appropriate |
| Automated testing | 15 | Representative unit/integration tests, invalid input, boundaries, and reproducible test plan |
| Code quality and maintainability | 10 | Cohesive classes, meaningful names, limited duplication, validation, and useful commits |
| Documentation and demonstration | 5 | README, design notes, sample data/output, screenshots or video, and disclosures |

## Performance expectations by difficulty

- **Easy:** the core operations are correct on small and medium synthetic inputs; explain the expected complexity.
- **Medium:** demonstrate a meaningful algorithmic choice and include at least one larger fixture or benchmark that reveals the trade-off.
- **Hard:** include a scalability discussion, a reproducible performance experiment or operation-count table, and explicit limitations for real-world deployment.

## Common deductions

- Missing or non-running tests: up to 15 points.
- No complexity analysis: up to 15 points.
- Required data structure replaced with a black-box library without explanation: up to 20 points.
- Sensitive data, secrets, or uncredited external material committed to the repository: score may be capped and the issue must be corrected before resubmission.
- Instructions that do not work from a clean clone: up to 10 points.
